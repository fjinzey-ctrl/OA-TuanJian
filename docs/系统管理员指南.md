# 系统管理员指南

系统管理员不属于任何支部，只维护平台级事务、公共资料、支部目录、容量、备份和支部管理员。

## 平台用户

- 查看平台账号总数以及每个用户的姓名、学号、角色、状态和唯一支部归属。
- 使用关键词、身份、所属支部和账号状态组合筛选用户。
- 为平台内任意用户生成仅显示一次的临时密码，并强制其下次登录修改密码。
- 经二次确认永久删除平台账号；当前登录账号、平台最后一名系统管理员和每个支部最后一名有效管理员受到保护。
- 系统管理员任命支部管理员或建立支部首位管理员时，可以复用未归属账号并保留原密码；已属于其他支部或属于系统管理员的账号不能重复加入。

## 支部与容量

- 查看全平台支部数量、成员数量和管理员数量。
- 查看平台文件实际总占用及分类占用。
- 点击支部卡片进入独立详情页。
- 修改支部名称、简称、简介、组织信息、负责人、预计毕业时间、文件用途和空间配额。
- 每次修改会向该支部全体管理员发送包含操作人、时间和变更明细的通知。

## 支部管理员

- 可输入学号，在指定支部现有有效成员中核验并任命管理员。
- 可将支部管理员降级为普通成员，账号和历史内容继续保留。
- 支部只剩一名管理员时，平台会阻止其被降级。

## 平台通知

- 可向全平台或指定支部发布通知。
- 可选择管理员、编辑和成员等接收身份。
- 支持定时发布、富文本、链接、图片和附件。
- “通知存档”可按分类、范围和关键词查阅人工通知与自动通知，并查看接收范围、定向接收人、时间、附件数量和阅读情况。

## 公共资料

- 统一维护团徽、团旗、团歌和使用规范。
- 公共资料面向所有已登录用户，不属于任何单一支部。

## 完整备份

- 在支部详情页启动备份。
- 等待整理和下载进度完成，期间不要离开页面。
- 备份成功后，支部管理员会收到包含备份编号、数据量、条目数、操作人和北京时间的通知。
- 支部数据在备份过程中发生变化时，应重新生成最新版备份。

## 支部删除

- 只有最新版支部备份已成功下载时才能发起删除申请。
- 申请发送给该支部全部管理员。
- 首位管理员的同意或拒绝决定会锁定本轮申请。
- 同意后仍需系统管理员再次确认才能执行永久删除。
- 删除决定会通知系统管理员和支部全体成员。
- 支部最终删除后，原成员账号和头像会保留并变为暂未加入支部；支部业务内容和文件仍按审批结果删除。

## 容量保护

- 平台实际总占用达到免费额度的 90% 时，系统自动向全平台发出整理提醒。
- 达到 95% 时暂停新增文件、头像、通知附件和其他会增加存储的操作。
- 保护状态下应优先完成必要备份，再清理不再需要的资料。

# System Administrator Guide

System administrators do not belong to any branch. They maintain only platform-wide matters, public official resources, the branch directory, capacity, backups, and branch administrators.

## Platform Users

- View the total number of platform accounts and each user's name, student ID, role, status, and unique branch affiliation.
- Combine keyword, role, branch-affiliation, and account-status filters to narrow the user list.
- Generate a one-time temporary password for any platform user and require a password change at the next sign-in.
- Permanently delete a platform account after secondary confirmation. The current signed-in account, the platform's last system administrator, and the last active administrator of every branch are protected.
- When appointing a branch administrator or establishing the first administrator of a branch, a system administrator can reuse an unassigned account and preserve its current password. An account that belongs to another branch or is already a system administrator cannot be added again.

## Branches and Capacity

- View the platform-wide counts of branches, members, and administrators.
- View actual total platform file usage and categorized usage.
- Select a branch card to open its dedicated details page.
- Update the branch name, short name, description, organization details, person in charge, expected graduation time, file-purpose description, and storage quota.
- Every update sends all administrators of that branch a notification containing the operator, time, and detailed changes.

## Branch Administrators

- Enter a student ID to verify an existing active member in the specified branch and appoint that member as an administrator.
- Downgrade a branch administrator to an ordinary member while retaining the account and historical content.
- When only one administrator remains in a branch, the platform prevents that administrator from being downgraded.

## Platform Notifications

- Publish a notification to the whole platform or selected branches.
- Select administrator, editor, and member audiences.
- Use scheduled publishing, rich text, links, images, and attachments.
- “Notification Archive” can filter manual and automatic notifications by category, scope, and keyword, and shows the audience, direct recipient, time, attachment count, and read status.

## Public Official Resources

- Centrally maintain the Youth League emblem, flag, anthem, and usage guidelines.
- Public official resources are available to every signed-in user and do not belong to a single branch.

## Complete Backups

- Start a backup from the branch details page.
- Wait until the preparation and download progress is complete, and do not leave the page during the process.
- After a successful backup, branch administrators receive a notification containing the backup ID, data size, item count, operator, and Beijing time.
- If branch data changes during backup preparation, create a new current backup.

## Branch Deletion

- A deletion request can be initiated only after the latest branch backup has been downloaded successfully.
- The request is sent to all administrators of that branch.
- The first administrator's approval or rejection locks the current request.
- Even after approval, a system administrator must confirm again before permanent deletion is executed.
- The deletion decision is sent to the system administrator and every member of the branch.
- After final branch deletion, former member accounts and avatars remain and become unassigned. Branch business content and files are still deleted according to the approved decision.

## Capacity Protection

- When actual platform-wide usage reaches 90% of the free allowance, the platform automatically sends a cleanup reminder to all users.
- At 95%, the platform pauses new files, avatars, notification attachments, and other operations that would increase storage usage.
- While protection is active, complete necessary backups first and then remove materials that are no longer needed.
