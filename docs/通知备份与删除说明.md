# 通知、备份与支部删除说明

v2.1.11 在支部删除审批区域增加流程图，帮助核对最终备份、双方下载、全体管理员表决和系统管理员最终确认。业务操作成功后异步发送通知的原则不变，通知暂时失败不会把已完成的业务操作误报为失败。

支部删除采用严格顺序：系统管理员生成最终版备份；系统管理员与至少一名支部管理员完成下载；系统管理员发起删除请求；对应支部全体管理员逐人表决；全部同意后由系统管理员最终确认。备份因支部数据变化失效，或任何管理员不同意时，本轮申请立即失效，后续必须重新生成最终版备份并从头开始。

v2.1.6 明确：支部删除处理支部归属和业务资料，不永久删除成员平台账号。账号、密码、头像、可信设备及登录记录会保留，成员可在以后重新加入支部。

通知详情会覆盖在仍保持展开的通知中心上，关闭详情后可继续浏览原列表；“前往相关页面”会在跳转前自动关闭详情和通知中心。通知中心支持刷新、仅看未读和全部标为已读；查看过列表但尚有未逐条阅读内容时，铃铛使用小红点提示，后续新通知或同一内容再次异动后恢复数字提示。

同一内容首次发布后只保留一条通知，后续修改更新该通知并追加完整异动时间线，同时把该条目重新排到通知列表顶部。已经读过的通知会重新变为未读；尚未阅读时仍保持一条未读，不重复堆积。新成员不集中接收加入前的支部消息，只看到欢迎通知以及近两个月全平台通知；该时段为空时回退最近两条。

## 通知类型

- 平台通知：由系统管理员发布，可面向全平台或指定支部。
- 内容通知：本支部发布新公示、团建或团费内容时自动产生。
- 身份通知：账号角色在管理员、编辑、成员之间调整时自动产生。
- 支部资料通知：系统管理员修改支部信息时发送给该支部管理员。
- 备份通知：系统管理员完成支部备份后发送给该支部管理员。
- 删除流程通知：包含删除申请、管理员决定和最终处理状态。
- 设置与内容更新通知：支部设置或已发布内容发生变化时自动产生。
- 平台升级通知：系统升级后自动向相关用户说明本次可见变化。

所有自动管理通知都会尽量注明操作人、操作时间和变更明细。系统管理员可在分类存档中按类型、范围和关键词查找人工与自动通知；支部正文继续保持隔离。页面中的管理时间统一标注为 `GMT+8:00`。

## 备份内容

完整支部备份包括：

- 公示、团建和团费内容。
- 草稿、已发布和已归档状态。
- 作者、日期、发布时间和修改记录。
- 内容对应的原附件。
- 支部基础信息和组织信息。
- 成员账号基础信息与身份。
- 当前缴费状态和历史缴费归档明细。

备份文件按模块和内容条目整理，便于离线查阅与长期保存。

## 删除审批规则

1. 系统管理员生成最终版备份并完整下载。
2. 至少一名当前支部管理员完整下载同一份最终版备份。
3. 备份生成后如发生内容、资料、成员、设置或缴费数据变化，备份立即失效，流程从第一步重新开始。
4. 双方下载凭证齐备后，系统管理员发起本轮支部删除申请，并固定本轮需要表决的全部支部管理员名单。
5. 名单中的每位管理员分别选择同意或不同意；全部同意后申请才可进入最终确认。
6. 任何一位管理员不同意时，本轮申请和对应备份立即失效，后续必须重新生成最终版备份并从头开始。
7. 系统管理员最终确认前，服务端再次核验备份有效、下载凭证完整、全体同意且没有拒绝票。

# Notifications, Backups, and Branch Deletion

## Notification Types

- Platform notification: published by a system administrator to the whole platform or selected branches.
- Content notification: generated automatically when a branch publishes a new notice, activity review, or fee item.
- Role notification: generated automatically when a member is appointed or reassigned as an administrator, editor, or ordinary member.
- Branch-details notification: sent to branch administrators when a system administrator changes branch information.
- Backup notification: sent to branch administrators after a system administrator completes a branch backup.
- Deletion-process notification: covers the deletion request, an administrator's decision, and final processing status.
- Settings and content-update notification: generated automatically when branch settings or published content changes.
- Platform-release notification: generated after a system update to explain user-visible changes.

Every automatic administrative notification identifies the operator, operation time, and detailed changes whenever applicable. System administrators can find both manual and automatic notifications in a categorized archive by type, scope, and keyword, while branch content remains isolated. Administrative times shown on the page are labeled `GMT+8:00`.

## Backup Contents

A complete branch backup includes:

- Notices, activity reviews, and Youth League fee content.
- Draft, published, and archived statuses.
- Authors, dates, publication times, and revision records.
- Original attachments associated with each content item.
- Basic branch and organization information.
- Basic member account information and roles.
- Current fee statuses and detailed historical fee archives.

Backup files are organized by module and content item for convenient offline review and long-term retention.

## Deletion Approval Rules

1. A system administrator generates and completely downloads the final backup.
2. At least one current branch administrator completely downloads the same final backup.
3. Any later change to content, resources, members, settings, or fee data invalidates the backup and restarts the workflow.
4. After both download requirements are satisfied, the system administrator starts the deletion request and captures the complete administrator voting list.
5. Every administrator on that list votes independently. The request advances only after unanimous approval.
6. Any rejection immediately invalidates both the request and its backup. A later attempt must begin with a new final backup.
7. Before final deletion, the server rechecks backup validity, download evidence, unanimous approval, and the absence of any rejection.
# 2.1 通知附件说明

通知正文图片与附件区文件均通过登录鉴权地址读取。系统通知存档会保留附件名称、类型和入口；是否显示在正文或附件区由发布者分别决定。备份与删除规则不因本次显示修复而改变。
